Decision log

The main product decisions behind Callmeter, with the reasoning and the alternatives I considered. Newest at the bottom.

Decisions

0113 Oct
Problem selection

Choose the problem on usefulness and viability, and only what I can prove

Checks
Evidence of demand. Not already shipped or clearly on the roadmap. Data reachable through a public API. Value that can be measured. A working prototype in about two to three weeks. And one check added for this platform: the result has to be provable on a free Personal Developer Instance against the platform's own numbers.
Not used
Fit with my own past experience. It can break a tie, nothing more.
0213 Oct
DroppedAlready shipped

Drop ideas the platform already covers

Why
Searches with no results (AI Search analytics), duplicate knowledge articles (Knowledge Center), CMDB data quality, test coverage, notification noise and missing ACLs all have native features in recent releases. Reassignment ping-pong is partly covered by the Insights dashboard and Process Mining.
0313 Oct
DroppedCan't test

Write about AI assist spend, don't build it

Why
Assists are now metered and an agent run can cost 25 to 150 assists, so the demand is real. But Now Assist and AI agents can't be installed on a free developer instance, so I can't check any number against the platform. A tool I can't verify isn't worth showing.
Instead
A short written note, kept separate from the build.
0413 Oct
Build

Build the Integration Hub transaction tracer, with the SLA audit as a fallback

Why
Integration Hub is now part of every tier edition, transactions come from a yearly allowance, and the native dashboard doesn't show which flow spent them or whether the call was useful. The platform keeps its own ledger, so every number can be checked.
Fallback
An audit of how much SLA time On Hold hides across all tickets. Fully provable on a developer instance, but without a dated reason to care now.
0513 Oct
Method

Spike first, with written kill rules

Stop if
The REST step isn't available on a free instance; the ledger shows nothing 48 hours after the test runs; or the counts don't match and one more round can't explain it.
Prediction
Four flows, 10 runs, 8 transactions: 0 for the control, 3 for one call, 3 for call before check (2 of them wasted), 2 for the failing call.
0614 Oct
Naming

Call it Callmeter, with no platform name in it

Why
It says what the tool measures: calls that cost money. ServiceNow's trademark guidelines don't allow their marks, or anything that looks like part of their "Now" family, in a third party's product name, repository name or domain. Compatibility goes in the description instead, as in "Callmeter, for use with ServiceNow® Integration Hub".
Also
Every page carries the trademark attribution and says the project isn't affiliated with ServiceNow, Inc. The pages don't copy ServiceNow's colours or design.
0714 Oct
SpikePassed

The spike passed: 8 of 8

Result
The usage ledger showed 6 transactions for the shared GET action and 2 for the failing action, exactly as predicted. All 8 calls were linked to their flow runs through the API.
Learned
Failed calls are billed and their runs still show Complete. The ledger counts per action, so flows that share an action can't be told apart. The ledger updates in a batch, not live.
0814 Oct
Trust

Read-only, and a dedicated account for real use

Decision
The tool only reads two tables and writes nothing to the instance. For real instances, the setup guide will recommend a separate account set to Web Service Access Only with the minimum read access, instead of an admin login.
Why
An admin should be able to say yes without a security review of the whole instance. The 2026 Basic Auth restriction also pushes API access toward dedicated accounts.
0914 Oct
Method

Define waste as "the run changed nothing", and read it from record history

Rule
A transaction bought nothing if its call failed, or if the run that made it changed nothing on its record. Changes come from sys_audit, filtered to the flow's account and the run's own record and time window.
Why
It needs no knowledge of what each flow is meant to do, so it works on any flow. It flagged 5 of 5 such runs in the lab, including my own baseline flow.
Limits
A flow that changes a different record, sends an email or calls out only to read data will look like it changed nothing. The report will call these "no visible effect" and let the admin judge, rather than call them waste outright.
